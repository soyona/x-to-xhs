# Product Context

## 目标用户

- 需要把海外 X 内容转化为中文内容的创作者。
- 关注 AI 工具、开发者效率、Agent 与 Coding 工作流的人群。
- 希望使用免费或低成本模型完成内容生产的个人用户。

## 核心用户流程

1. 在 `01 粘贴 X 内容` 输入完整帖子或单条帖子 URL。
2. 点击“生成小红书长文”。
3. 服务端解析 URL（如有），把原文注入 Markdown 提示词。
4. 按 Gemini → Groq Qwen → OpenRouter Free 顺序调用模型。
5. `02 小红书长文` 按 7 步发布流程展示可复制内容。
6. `03 规范检查` 自动显示通过和失败条件。
7. 如果自动检查失败，用户可执行自动修复，完成后重新检查。
8. 用户人工确认内容质量，最后在小红书完成排版和发布。

## 小红书 7 步发布流程

| 步骤 | 产品行为 |
|---|---|
| 01 输入长文标题 | 复制 Markdown 第一行标题的纯文本 |
| 02 输入长文正文 | 复制正文，不含标题、摘要、标签和自查 |
| 03 点击一键排版 | 用户在小红书操作，生成封面与内容卡片 |
| 04 修改发布标题 | 再次复制标题，检查 20 字上限 |
| 05 输入正文描述 | 优先使用“正文小结 / 摘要”，上限 1000 字 |
| 06 输入标签 | 复制同一行的 `#标签`；缺失时使用兜底标签 |
| 07 检查并发布 | 用户确认封面、正文、标题、描述和标签 |

## 内容合同摘要

完整规则以 [`Long-form-post-prompt.md`](../Long-form-post-prompt.md) 为准。

- 标题：18–20 字。
- 正文：4200–5200 字。
- 开头：380–450 字。
- 实战落地：不少于 1200 字。
- 摘要：220–280 字，同时不超过发布页 1000 字限制。
- 标签：8–10 个唯一标签，同一行，每个以 `#` 开头。
- 固定尾部顺序：
  1. `## 正文小结 / 摘要`
  2. `## 推荐标签`
  3. `## 【审稿自查】`
- 审稿自查：3–5 条风险或优化建议。

## 规范检查的信息架构

### 自动检查：11 项

- 标题：字数。
- 正文内容：总字数、开头、主体结构、实战落地。
- 正文小结 / 摘要：摘要字数、发布描述。
- 推荐标签：标签数量、标签格式。
- 输出结构：分区与顺序。
- 审稿自查：风险点数量。

### 人工内容复核：8 项

- 二度创作。
- 案例与洞见。
- 语气与表达。
- 实战完整性。
- 结尾互动。
- 排版可读性。
- 摘要与标签质量。
- 审稿建议质量。

人工项只提示“发布前确认”，不参与自动失败计数和自动重写。

## 关键 UX 约束

- 三个主面板保持同一高度。
- 整页不产生滚动条；各面板内部独立滚动。
- 移动端仍保持三段固定高度，而不是把整个页面纵向撑开。
- 输入说明放在文本框 placeholder，不额外占用正文空间。
- 生成后不能要求用户一次复制整个 Markdown。
- API 配置入口固定在页面右上角。
