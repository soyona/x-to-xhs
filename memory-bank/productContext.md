# Product Context

## 目标用户

- 需要把海外 X 内容转化为中文内容的创作者。
- 关注 AI 工具、开发者效率、Agent 与 Coding 工作流的人群。
- 希望使用免费或低成本模型完成内容生产的个人用户。

## 核心用户流程

1. 在 `01 粘贴 X 内容` 输入完整帖子或单条帖子 URL。
2. 选择“长文笔记”或“图文笔记”，按需选择或编辑对应提示词方案。
3. 点击当前模式的生成按钮。
4. 服务端解析 URL（如有），把结构化来源信息和原文注入当前 Markdown 提示词。
5. 按 Gemini → Groq Qwen → 智谱 GLM → 硅基流动 Qwen →
   OpenRouter Free 顺序调用模型。
6. `02 发布素材` 不模拟小红书发布流程，直接展示用户需要复制或下载的内容。
7. 长文模式展示标题、正文、正文描述和标签；图文模式展示标题、图片组、
   正文描述和标签。每一部分都在内容旁提供复制、下载或重新生成操作。
8. 用户人工确认内容质量，最后在小红书完成排版和发布。

首次生成成功后服务端自动创建历史记录。用户可以通过
右上角“查看历史”查看、载入或删除记录，载入本身不调用模型。

## 发布素材工作台

| 部分 | 产品行为 |
|---|---|
| 标题 | 可编辑、复制和重新生成；候选明确提供复制与采用操作 |
| 正文 | 可编辑、预览、复制富文本、导出 Markdown、重新生成并采用新版本 |
| 正文描述 | 使用当前正文摘要，可编辑、复制和重新生成；正文变化后就近提示复核 |
| 标签 | 可编辑、复制和重新生成；没有可信趋势数据时只标记为基于正文生成 |

图文模式在同一信息结构中以“图片组”替换“正文”。图片区使用一张大预览和
横向缩略图，支持逐张切换、编辑、下载当前图片、下载全部图片和整体重新生成。

## 内容合同摘要

长文完整规则以 [`prompts/longform/default.md`](../prompts/longform/default.md) 为准。

- 标题：默认 16–20 字，恰好 1 个 Emoji；默认使用“超全干货”，仅正文
  实际超过 8000 字可以使用“万字深度”。
- 正文：不设最低字数，按原文信息量自然展开；最大 10000 字。
- 开头：建议 150–450 字，短主题可以更精简。
- 实战落地：按主题适用性展开，不设最低字数，不得为凑篇幅虚构内容。
- 摘要：220–280 字，同时不超过发布页 1000 字限制。
- 主体：按内容需要设置 2–15 个连续编号大章节；每章 1–3 个小节点。
- 卡片切分：由小红书“一键排版”自行完成；正文禁止使用 `---`、
  “未完待续”等伪分页信号。
- 标签：恰好 8 个唯一标签，同一行，每个以 `#` 开头。
- 固定尾部顺序：
  1. `## 正文小结 / 摘要`
  2. `## 推荐标签`
- 正文内部保留`#`、`##`、`-`和`1.`表达标题与列表语义；不使用
  加粗、引用、表格或代码围栏。
- 复制正文时优先写入`text/html`富文本，同时提供去除井号、把`-`
  转为`•`的`text/plain`兜底，避免平台不解析 Markdown 时显示标记。

## 提示词配置

- `prompts/longform/default.md` 是长文系统默认提示词，包含全局、标题、正文、
  摘要、标签和固定输出协议六个模块。
- 页面“创作设置”只管理提示词方案，开放全局、标题、正文、摘要和标签
  五个模块。
- 长文自定义方案保存在 `.local-data/prompts/longform.json`；切换方案后，完整生成和
  局部重新生成使用同一规则来源。
- 全局规则可随页面方案覆盖；固定输出协议仍由系统保护。
- 默认模板和当前方案可以下载为完整 Markdown；结构不变的模板可以上传并
  导入为新方案。
- 页面不执行内容 validation，不因字数、Emoji、章节或标签规则拒绝模型结果。
- JSON 是否可解析、结果是否为空和候选数量属于技术协议，继续保留。

### 图文提示词主题

- 图文笔记由标题、图片组、正文描述和标签组成；图片组对应长文笔记的正文。
- 图片提示词沿用长文提示词方案的管理体验：系统默认模板、当前方案、
  新建副本、保存、删除、下载和上传保持一致。
- 每个图片提示词使用固定 Markdown 结构，页面只编辑既有模块内容，不得
  改变、增删或重排结构；用户也可以直接编辑同结构 Markdown 文件后导入。
- 图片模板按主题风格保存，例如“商务简约”；主题同时控制封面、内容页、
  排版风格、配色、装饰元素、总字数与阅读时间元素和页码规则。
- 图文标题、正文描述和标签使用图文方案内自己的独立模块，不读取长文内容
  规则；图片组使用同一图文方案生成。局部重新生成沿用当前图文方案。
- 固定输出协议、图片数量、格式、文件大小和分辨率属于系统保护的技术协议，
  不向页面方案开放为自由结构。

## 图文笔记流程

| 部分 | 产品行为 |
|---|---|
| 标题 | 与长文标题使用一致的候选预览、复制、采用和重新生成交互 |
| 图片组 | 对应长文正文；按照当前主题提示词生成最多 18 张图片，支持整体重新生成和逐页预览 |
| 正文描述 | 对应长文流程的“04 正文描述”，支持复制和重新生成 |
| 标签 | 与长文标签使用一致的复制、数据模式说明和重新生成交互 |
| 预览与下载 | 参照小红书图文翻页方式预览；支持下载当前图片、选中图片或全部图片 |

图文图片单张最大 32MB，只允许 PNG、JPG、JPEG 或 WebP；默认使用
3:4 且不低于 720×960 的画布，并允许在官方推荐的 3:4 至 2:1 比例内配置。

## 关键 UX 约束

- 两个主面板保持同一高度。
- 整页不产生滚动条；各面板内部独立滚动。
- 移动端仍保持两段固定高度，而不是把整个页面纵向撑开。
- 输入说明放在文本框 placeholder，不额外占用正文空间。
- 生成后不能要求用户一次复制整个 Markdown。
- `02` 展示唯一的结构化正文源稿；富文本和纯文本兜底必须由该字段
  确定性派生，不得维护两份独立正文。
- `02` 的 Markdown 导出与复制共用同一正文数据源；文件只用于小红书
  标题与正文编辑页的“从文件导入”，并提示导入会覆盖已有正文。
- 标题、正文或图片、正文描述、标签按照最终发布素材顺序平铺，不使用步骤栏、
  完成状态或复制清单重复展示内容。
- 复制、下载、重新生成与对应内容就近展示；正文复制与 Markdown 导出并列，
  不得以操作列压缩正文预览宽度。
- 标题和标签使用紧凑预览，正文描述使用中等预览，长文正文使用较高的
  内部滚动预览并支持展开或收起；不得因此破坏整页无滚动约束。
- 复制、下载和重新生成使用图标加文字的具名按钮；复制成功在按钮旁短暂显示
  “已复制”，按钮本身保持可见，并保留 `aria-label` 和键盘焦点状态。
- 标题候选只在对应标题区展示，每个候选明确提供“复制”和“采用”；初次生成
  与重新生成使用同一套展示和复制逻辑。
- 其他局部重新生成产生候选，不得自动覆盖当前内容；正文候选被采用后，
  04、05 分别标记为基于旧正文，直到用户重新生成或选择新候选。
- 没有可信趋势数据时，标签只能标记为“基于正文生成”，不得使用
  “实时热门”或“当前趋势”等文案。
- `02` 承载对应部分的复制、导出、候选选择和主动重新生成。
- API 配置入口固定在页面右上角。
- 页面右上角“设置”是唯一配置入口，01 输入区不重复显示偏好或入口。
- 固定输出协议和事实边界不向页面方案开放编辑；内容规则允许配置。
- “查看历史”与“设置”并列放在右上角，不占用 01/02 工作区高度。
- 历史默认按最近更新时间倒序；一次首次生成是一条记录。
- 载入历史后恢复原始输入和草稿，但不调用模型。
- 删除需要在历史弹窗内二次确认。
