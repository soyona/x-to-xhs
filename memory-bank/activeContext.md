## 已知问题：优先级高


### 修复问题描述不够细

`structure`、`fixed-format`、`tag-format` 等复合检查目前只给出“不完整”或“不正确”，没有说明具体缺失条件。

推荐改造：

```js
{
  actual: "缺少结尾",
  problem: "正文没有识别到结尾分区",
  repairInstruction: "保留现有正文，在实战落地后补充价值总结、趋势思辨和2–3个开放问题"
}
```

### 单个结构失败会触发整篇重生

`repairStrategy.js` 把任何 `structure` 失败都视为严重失败。即使其他十项通过、只缺少结尾，也会选择 `regenerate`。

期望：

- 单独缺少结尾、总览或一个主体标题：局部修复。
- 多个核心分区缺失或正文严重不足：整篇重生。

### 局部修复仍返回完整草稿

界面已经能从对应部分发起修复，并只把该部分失败项作为重点目标提交；但模型接口
仍返回完整 Markdown。当前按钮使用“修复此部分”，没有承诺只替换单个字段。
如果未来改为“重新生成本部分”，服务端必须提供真正的分区锁定与合并协议。

## 建议下一步

1. 为复合检查增加 `problem`、`missingReasons`、`repairInstruction`。
2. 重新定义 `repair` / `revise` / `regenerate` 的严重度规则。
3. 为局部修复增加服务端分区锁定与合并协议。
4. 增加场景测试：
   - 只缺结尾时不得整篇重生。
   - 只多一个额外分区时只删除该分区。
   - 只超标题字数时只改标题。
   - 第二次处理只提交剩余失败项。
