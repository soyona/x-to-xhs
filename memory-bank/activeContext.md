## 已知问题：优先级高

### 测试夹具缺失

`tests/xiaohongshuText.test.js` 依赖 `examples/demo1.md`。该文件当前不在
工作区，导致 `npm run test` 的 demo1 转换测试出现 `ENOENT`。

不要凭空重建示例内容；应从用户认可的原始文件恢复，或由用户授权后把测试改成
仓库内稳定的最小夹具。

### 修复问题描述不够细

`structure`、`fixed-format`、`tag-format` 等复合检查目前只给出“不完整”或“不正确”，没有说明具体缺失条件。

推荐改造：

```js
{
  actual: "缺少结尾",
  problem: "正文没有识别到结尾分区",
  repairInstruction: "保留现有正文，在实战落地后补充价值总结、趋势思辨和2–3个开放问题"
}
```

### 单个结构失败会触发整篇重生

`repairStrategy.js` 把任何 `structure` 失败都视为严重失败。即使其他十项通过、只缺少结尾，也会选择 `regenerate`。

期望：

- 单独缺少结尾、总览或一个主体标题：局部修复。
- 多个核心分区缺失或正文严重不足：整篇重生。

### 修复按钮附近缺少失败摘要

检查列表能显示失败项，但修复区域只显示通用说明和失败数量。应在消耗 Token 前列出“本次将修改什么”。
