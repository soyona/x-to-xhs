# UI System v1

本文件是应用界面的唯一视觉规范。它约束产品壳层、工作区、表单和操作控件。

## 设计原则

1. **任务优先**：页面只突出当前最重要的下一步，辅助操作降低视觉权重。
2. **跨流程一致**：相同行为必须使用相同组件、图标、顺序和反馈。
3. **紧凑但清晰**：采用适合桌面生产力工具的信息密度，不以装饰制造层级。
4. **复用成熟能力**：原生 HTML 负责基础语义，Lucide 负责图标；复杂菜单、弹层、
   焦点管理和组合键盘交互优先采用成熟的无样式组件，不自行实现底层引擎。

## 页面结构

- 页面保持两个核心工作区：`01 内容创作`、`02 小红书笔记`。
- 两侧面板标题栏高度、边框、标题层级和编号样式保持一致。
- 页面本身不滚动；内容只允许在面板内部滚动。
- 新功能必须进入现有两个工作区或既有弹窗，不得创建第三种页面壳层。

## 操作层级

| 层级 | 用途 | 视觉规则 |
|---|---|---|
| Primary | 生成或更新整篇笔记 | 品牌色实心；同一屏幕最多一个 |
| Secondary | 复制、下载当前结果、重新生成 | 中性描边，不与主任务竞争 |
| Ghost | 预览、编辑、低频辅助操作 | 透明背景，悬停时显示弱底色 |
| Danger | 取消或不可逆操作 | 仅使用危险色文字或弱底色 |

区块操作顺序从左到右固定为：

`查看或编辑 → 低频导出 → 重新生成 → 复制或下载当前结果`

结果操作始终位于最右侧。批量操作放在对应单项操作左侧，不得改变共有操作的顺序。

## 控件规格

- 控件高度只使用 `32px`、`36px`、`44px` 三档。
- 应用控件圆角统一使用 `8px`；面板圆角使用 `11px`。
- 常规图标使用 `16px`，紧凑图标使用 `14px`。
- 操作按钮文字使用 `12px`；主操作使用 `13px` 至 `14px`。
- 品牌色只用于 Primary、当前选择、焦点和必要状态，不用于装饰。
- 所有交互控件必须提供 hover、active、focus-visible、disabled 和 loading 状态。
- 成功或失败不能只依靠颜色表达；复制与下载成功应同时显示图标和文字。

## 组件使用规则

- 业务代码必须优先复用 `src/components/ui/**`。
- 操作按钮使用 `Button`；纯图标操作使用 `IconButton`。
- 同组操作使用 `ActionGroup`；模式切换使用 `SegmentedControl`。
- 图标统一从 `src/components/ui/icons.js` 引入，业务组件不得直接引入图标库。
- 业务组件不得再次声明 `MaterialAction`、`PublishingKitAction` 或同类按钮包装器。
- 业务 CSS 不得创建另一套按钮颜色、尺寸、圆角、阴影和状态。
- 专用结构控件（例如缩略图、流程导航）可以保留原生语义，但不得伪装成新的操作按钮体系。

## 状态与反馈

- Loading：保留按钮宽度，使用旋转指示和进行中动词，禁止用空白按钮代替。
- Success：操作按钮短暂显示勾选和结果文字，例如“已复制”“已下载”。
- Error：在操作附近显示明确错误，并允许重试。
- Disabled：降低对比度但仍保持标签可读；不得只移除鼠标事件。
- Focus：所有键盘可达控件使用统一焦点环，不得移除 outline 后不提供替代样式。

## 响应式规则

- 操作组空间不足时允许整体换行，不缩小文字或图标。
- 共有操作顺序在所有断点保持不变。
- 小屏下文字输入和内容预览占满可用宽度，操作组左对齐。
- 控件不得造成面板横向滚动。

## 变更治理

1. 新功能先组合现有组件，不得先在业务页面创建临时风格。
2. 现有组件无法表达需求时，优先扩展公共组件的语义变体。
3. 新增视觉语言、控件尺寸、颜色或组件变体必须获得用户明确授权。
4. 获得授权后，先更新本文件和公共组件，再修改业务页面。
5. `npm run check:ui` 必须通过；不得通过删除检查或扩大例外绕过规范。
