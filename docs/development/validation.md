# 项目验证规范

本文件是 x-to-xhs 的项目开发规范，仅补充验证操作细节。
`.codexrules` 的授权、安全和产品约束高于本文件；本文件不得扩大修改授权、
降低安全要求或改变产品契约。

## 环境与常用命令

要求 Node.js 20.18 或更高版本。

```bash
npm run dev
npm run check
```

- 仅在依赖缺失、`package.json` 已变化或用户明确要求时运行 `npm install`。
- 开发前端：`http://localhost:5173`
- 本地 API：`http://localhost:8787`
- 生产模式：先 `npm run build`，再 `npm start`

## 修改前检查

1. 修改前确认工作区状态，不覆盖用户已有改动。
2. 只做任务范围内的变更，不顺手重构无关模块。

## 默认验证矩阵

| 改动类型 | 默认验证 |
|---|---|
| 规则、README、纯文档 | `git diff --check` |
| 服务端或纯逻辑 | 定向测试；完成后运行完整检查 |
| React / UI | 定向测试和生产构建；行为代码变化时运行完整检查 |
| API Key 或安全配置 | 定向测试、完整检查和下文安全检查 |

## 验证执行与重跑

- 开发过程中优先运行相关测试文件；文件内包含已知无关失败时，使用测试名称
  过滤，只运行与改动直接相关的用例。
- 测试名称、测试说明或其他不影响行为的文字调整，与最终代码改动合并验证
  一次，不单独重复运行同一测试文件。
- 已知失败必须记录具体测试名称、失败原因及其与本次改动的关系；不得使用
  宽泛的“测试有问题”代替。
- 定向测试用于开发反馈，不得长期代替完整检查；已知失败修复后必须恢复一次
  `npm run check`。
- 对验证矩阵要求完整检查的代码改动，在所有修改完成后运行：

  ```bash
  npm run check
  git diff --check
  ```

- 如果完整检查因已知测试失败而在构建前停止，不重复运行同一测试套件；
  单独运行一次 `npm run build`，并准确报告既有失败。
- 如果发现本次改动引入的失败，修复相关代码后允许重跑；代码未变化时不得
  重复运行同一完整验证。

## 浏览器验证

- 默认不调用浏览器，不进行浏览器自动化或截图验证。
- UI 改动默认只执行单元测试、静态检查和生产构建。
- 只有用户在当前需求中明确要求“浏览器验证”“视觉验收”或“移动端验收”时，
  才允许调用浏览器。
- 未执行浏览器验证时，应明确报告：仅完成静态、测试和构建验证，浏览器交互
  尚未验收。
- 在不与系统、开发者、用户当前指令或 `.codexrules` 冲突的前提下，本项目
  验证规范优先于一般技能建议。

## API Key 与安全配置

涉及 API Key 时额外验证：

- `.env` 仍被 Git 忽略。
- `.env` 文件权限保持 `600`。
- `/api/health` 不包含 `apiKey`、`secret` 或 `token` 字段。

## 结果报告

- 区分定向测试、静态检查、生产构建、浏览器交互和人工验收的证据范围。
- 未执行的验证必须明确列出，不得把未验证路径报告为已通过。
